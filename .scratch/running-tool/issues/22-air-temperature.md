# 22: 有氧图改用 Open-Meteo 气温并标注高温周

**What to build:** 有氧图的每周温度改用 Open-Meteo 历史气温（手表没有温度，这条线现在一直为空），并在图上标注高温周。不做回归校正。

**Blocked by:** 19（温度校正），21（分析侧的数据清洗：同一批有效跑步）

**Category:** enhancement

**Status:** needs-triage

来源：[19 温度校正](19-temperature-correction.md) 的结论，用户 2026-10-31 确认的全部 5 条建议。

## 要求

- [ ] **气温获取和缓存**：分析包新增一个模块，从 Open-Meteo 历史天气接口（`archive-api.open-meteo.com/v1/archive`，`hourly=temperature_2m`，`timezone=GMT`）取逐小时气温，缓存在数据目录的 `raw/open-meteo/`。
  - 位置：路跑逐秒记录的经纬度中位数各取整到 0.1°，取跑步次数最多的格点；只发这一个格点和日期范围，不发逐次活动的坐标。
  - 覆盖范围：活动所在格点离主格点 ≤ 0.2° 的跑步才配气温，其余为 NULL。
  - 缓存：已缓存的日期不再请求，只补缺少的日期；请求失败时用已有缓存，不中断仪表盘。
  - 下载方式：本机 Python 的证书链验证这个站点会失败（19 的结论），实施时确认可用的方式（例如系统 `curl`），不能关闭证书验证。
  - 格点、城市名和坐标不写进仓库、日志或 JSON 接口。
- [ ] **每次跑步的气温**：跑步中点时刻（开始 + 总时长的一半）在前后两个整点间线性插值。
- [ ] **每周温度**：有氧图的周温度改为该周有效路跑气温的中位数，替换现在的 `records.temperature` 平均（`analysis/src/running/aerobic.py` 的 `temperature_c`，`dashboard/static/aerobic.js`）。不再读取 `records.temperature`。
- [ ] **高温周标注**：周气温中位数 ≥ 22 °C 的周在有氧图上标出。阈值放进 `config.toml`（例如 `[aerobic] hot_week_c = 22.0`），有默认值。有氧能力的值本身不校正。
- [ ] 仪表盘和 JSON 接口的方法说明写上：气温来源是 Open-Meteo、不做温度校正、高温周的定义。
- [ ] 测试用合成数据和本地假的气温缓存（不发真实请求）：插值、远离主格点的跑步没有气温、周中位数、高温周阈值两侧、缓存只补缺少的日期。
- [ ] README 说明 Open-Meteo 的用途、发送了什么（取整格点和日期）以及缓存位置。

## 不做

- 回归校正配速。19 的参考温度 17 °C（跑步时气温中位数）只记录，暂不使用。
- 多个格点、按活动分别取气温。
- 除 Open-Meteo 以外的天气服务。
