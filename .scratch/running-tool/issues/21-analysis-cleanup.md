**Category:** enhancement
**Summary:** clean the analysis package according to 18: pause threshold defaults to 10 s; aerobic fitness (and long-run EF and decoupling) excludes activities without GPS or altitude and activities with severe GPS drift.

**Current behavior:**
- `RunWalk.pause_gap_s` defaults to 30: only a sample gap > 30 s counts as a pause, and 10..30 s gaps are counted as time.
- Aerobic fitness filters only by activity type (`AEROBIC_TYPES`, road runs); treadmill-like activities without GPS and activities with GPS drift (inflated per-second speed) take part in the computation too. Long-run EF and decoupling share the same filter.
- The method description of aerobic fitness in the dashboard and the JSON API (`method`'s `description`, `params`) does not mention these two exclusion rules.

**Desired behavior:**
- `pause_gap_s` defaults to 10 (the `Config` default and the README config example). A value set explicitly in the user's `config.toml` takes effect as usual.
- For aerobic fitness to be valid, an activity must also satisfy: its per-second records have at least one non-null latitude/longitude and one non-null altitude; the accumulated seconds with per-second speed > `max_speed_mps` are ≤ `max_fast_s`. Activities that fail do not enter aerobic fitness, long-run EF or decoupling, but enter volume and training load as usual.
- Both thresholds go into `[aerobic]` in `config.toml`: `max_speed_mps` (default 7.0), `max_fast_s` (default 60), into the `Aerobic` dataclass, with the README example updated.
- The method description states these two exclusion rules and their thresholds.
- Places in 18's notebook that pre-filter by these two rules may switch to using the analysis package's result directly (optional).

**Key interfaces:**
- The default of `RunWalk.pause_gap_s`.
- The `Aerobic` dataclass gains `max_speed_mps: float` and `max_fast_s: int`, read by `load_config`.
- The validity check of `aerobic_runs(db, config, ...)` (the `valid` column); the same check is used for EF and decoupling in the long-run module. Ideally there is a single check function shared by both.
- The `method` of the aerobic fitness JSON (keeping the existing `{name, description, params}` structure).
