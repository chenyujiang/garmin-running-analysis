## Agent Brief

> *This was generated by AI during triage.*

**Category:** enhancement
**Summary:** add an Open-Meteo data source to `runsync`: compute the 0.1° grid point of the usual running location, request hourly air temperature only for missing dates, archive it as is, and load it into a new table in the analysis database.

**Current behavior:**
`runsync sync` runs two data sources in turn, the Personal API and garminconnect (each independent, writing a cooldown marker when rate-limited, see `sync_all` and `cooldown`), and each data source records one row in `sync_runs`. The analysis database has no air temperature at all: `records.temperature` is all NULL (the FR245 Music's FIT files do not record temperature). 19 left a cache file by hand in the data directory's `raw/open-meteo/` (`hourly_temperature_2m_<start>_<end>.json`), which does not record the requested grid point.

**Desired behavior:**
- **Grid point**: take road-run activities (`running`, `street_running`, matching the analysis package's `AEROBIC_TYPES`) that have GPS; round each activity's median latitude and longitude to 0.1°; the most frequent grid point is the main grid point. Without any GPS, nothing is requested; `sync` prints one line explaining this and skips it.
- **Request**: `https://archive-api.open-meteo.com/v1/archive`, with only the parameters `latitude`, `longitude` (main grid point, one decimal), `start_date`, `end_date`, `hourly=temperature_2m`, `timezone=GMT`. No key needed. The date range is the dates not yet archived between the date of the earliest road run and "today − 2 days"; archived dates are not requested again. One request may cover the whole missing range (5 years is about 46,000 hours, a response of about 1 MB).
- **Archive**: the response is written as is to `raw/open-meteo/` (atomic write), together with the grid point and date range of the request (in the file name or a metadata file beside it, as implementation decides), because the latitude and longitude in the response are the model's grid point, not the requested one. The old cache left by 19 does not record its grid point and need not be supported (ignore it; the first `sync` requests all dates again). When the main grid point changes, only missing dates are requested for the new grid point; the old grid point's archive is kept.
- **Analysis database**: a new migration creates a table (e.g. `hourly_weather`), one row per grid point per hour: `grid_lat`, `grid_lon` (the requested 0.1° grid point), `time_utc` (following the existing time column format), `temperature_c`; the primary key is grid point plus time. `sync` loads after archiving; `rebuild` walks all of `raw/open-meteo/` and reloads it, with the same result as `sync`.
- **Failure handling**: Open-Meteo is an independent data source. On a network error or non-2xx response this data source is recorded as failed and the other two continue as usual; on a 429 the existing cooldown mechanism is reused (with its own cooldown marker). `sync_runs` records one row with `source = 'open_meteo'` (update the column comment of `sync_runs`).
- **Privacy**: grid points and coordinates appear only in the data directory (raw archive and analysis database). `sync` output, error messages and logs must not contain coordinates; HTTP library errors often include the full URL, which must be stripped (e.g. `reqwest::Error::without_url`). Output only states the number of hours and the date range.
- **Certificates**: the local Python's certificate chain fails to verify this site (see 19), while the system `curl` (schannel) works. The Rust side uses the existing HTTP client and verifies certificates normally; if verification fails, switch the TLS backend or the root certificate source, never disable verification.

**Key interfaces:**
- A new air temperature data source trait (modelled on `ActivitySource` and `MetricsSource`), so tests can inject a fake data source; the real implementation uses the existing `reqwest` client.
- `sync_all`'s report `SyncAllReport` gains an `Outcome` for Open-Meteo; the `sync` command prints one line for it.
- `rebuild`'s `RebuildReport` gains the number of air temperature hours loaded.
- A new migration (numbered after the current last one).
